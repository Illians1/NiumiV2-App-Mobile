## Règles de travail apprises pendant l'étape

- `export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home` avant tout
  `./gradlew`.
- Ne jamais `am force-stop com.niumi.app` pendant un protocole : cela supprime l'alarme (§20).
- `connectedDebugAndroidTest` sur `:app` désinstalle Niumi et efface ses données : prévenir
  l'utilisateur, qui doit refaire l'onboarding ensuite (`installDebug` seul conserve les données).
  Les modules `:core:system` et `:feature:setup` seuls ne touchent pas à l'application.
- HyperOS annule parfois les demandes d'installation des APK de test : surveiller et rejouer les
  modules refusés.
- L'instant fiable d'une alarme dans `dumpsys alarm` est le `origWhen` de l'en-tête `Alarm{…}`
  (epoch en ms), pas la ligne de détail.
- Avant une question de conception, expliquer le mécanisme et les implications en langage simple,
  puis les options avec leur coût ; l'utilisateur tranche.
- Les specs sont mises à jour dans le même changement que le code ; aucune limite n'entre dans
  l'aide sans mesure.
